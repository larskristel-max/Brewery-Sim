# Phase A Prototype

## First Playable Target

Phase A defines the smallest playable brewery simulation loop needed to validate the core game concept. The target is intentionally narrow and should prioritize proving that the basic production and economy flow is fun and understandable.

The first playable target includes:

1. A single-room brewery.
2. One brewer.
3. One kettle or brew station.
4. One fermenter.
5. A basic brew → ferment → package → sell → upgrade loop.
6. A minimal economy.
7. No polish requirement.

## Core Loop

Players should be able to:

1. Start a brew at the kettle or brew station.
2. Move the batch into the fermenter when brewing is complete.
3. Package the finished product.
4. Sell packaged beer for money.
5. Spend money on a simple upgrade that improves the next pass through the loop.

## Economy Scope

The Phase A economy should be deliberately simple. It only needs enough structure to support the brew → ferment → package → sell → upgrade loop. Complex pricing, taxes, compliance, market simulation, and long-term financial modeling are outside the scope of this prototype.

## Polish Expectations

Phase A does not require final art, animation, audio, UI refinement, balance, onboarding, or production-grade content. Temporary assets, rough interfaces, debug controls, placeholder values, and simplified interactions are acceptable if they make the core loop playable.

## Not in Phase A

The following features are explicitly excluded from Phase A:

- Staffing depth.
- Excise.
- Traceability.
- Multiple sites.
- Advanced automation.
- Complex UI.
- Operon sync.
